# Finance Research Agent — Setup Guide (Brand-New Machine → First Report)

A single, beginner-friendly, copy-paste guide that takes you from a **clean
computer with nothing installed** to a **finished research report** generated by
the Finance Research Agent (FRA) running against a **local LLM (Ollama)**.

This guide is **cross-platform-aware but primary-targets Windows / PowerShell**
(the exact commands below are PowerShell). macOS/Linux equivalents are noted
inline where they differ.

> Everything here is grounded in the actual code (`src/cli.py`,
> `src/llm/factory.py`, `requirements.txt`, `.env.example`, and the profile
> YAMLs). For deeper reference material this guide intentionally points to the
> three companion docs at the repo root rather than duplicating them in full:
>
> - **`OLLAMA_SETUP.md`** — the full Ollama provider deep-dive + verification.
> - **`RUN_OPTIONS.md`** — every CLI flag, env var, and profile field.
> - **`WORKFLOW.md`** — a plain-language tour of what the pipeline does internally.

> **Disclaimer (from the project).** FRA produces educational/research output.
> It is **not financial advice**, places **no real orders**, and uses **free
> public data** that may be stale or wrong. Always verify before acting.

---

## 1. Overview — what you'll end up with

When you finish this guide you will have:

- A working **conda environment** named `fra` (Python 3.13.x) with all Python
  dependencies installed.
- A running **Ollama** server with the default model **`llama3.1:8b`** pulled
  locally (no API keys, no cloud calls).
- A generated, timestamped **Markdown report** (and an **Excel `.xlsx`**
  workbook) in the `reports/` folder, e.g.
  `reports/20260622-220815-india_adult-best-IT-stocks-in-India.md`.
- A console **Top picks** table + a **Data health** line for the run.

The pipeline ranks the "best" stocks to *research* for a theme (e.g. *"best IT
stocks in India"*) or a single ticker (e.g. `SAP.DE`), blending a deterministic
**factor engine** (the math) with **LLM analysts** (the prose). The LLM is only
allowed to interpret the numbers — it never invents figures.

## 2. Prerequisites

| Requirement | Why | Notes |
|---|---|---|
| **OS** | Any | This guide shows Windows/PowerShell; macOS/Linux noted inline. |
| **~10 GB free disk** | The default model (`llama3.1:8b`) is a **~4.9 GB** download, plus conda env + caches | Have headroom; the first model load also uses RAM. |
| **~8 GB+ RAM** | To load an 8B model locally | An 8B model on CPU is usable but not fast (see runtime note in §11). |
| **Internet (first run)** | To install tools, pull the model, and fetch market data (yfinance/Stooq/GDELT) | After setup the LLM is fully local; data fetch still needs the network. |
| **A terminal** | To run commands | On Windows use **PowerShell** (not the old `cmd`). |

You do **not** need any paid API key. Ollama is local and free.

## 3. Step 1 — Install base tooling (git, conda) and get the code

### 3a. Install Git

Git lets you clone the repository (and is generally required for development).

```powershell
winget install --id Git.Git -e
```

> macOS: `brew install git`  ·  Linux (Debian/Ubuntu): `sudo apt install git`

### 3b. Install Miniconda (recommended) — or use venv as an alternative

**Recommended: Miniconda** (gives you the `conda` command used throughout this
guide, matching the verified `fra` env on this machine).

```powershell
winget install --id Anaconda.Miniconda3 -e
```

After install, **open a new terminal** so `conda` is on PATH. Verify:

```powershell
conda --version
```

> If `conda` isn't recognized, open the **"Anaconda Prompt (Miniconda3)"** from
> the Start Menu, or run `conda init powershell` once and reopen PowerShell.
>
> macOS/Linux: install Miniconda from <https://docs.conda.io/projects/miniconda/>
> then restart your shell.

**Alternative: plain `venv`** (no conda). Skip the conda steps in §4 and instead
do, from inside the project folder:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

(This requires a system Python 3.11+ already installed, e.g.
`winget install --id Python.Python.3.13 -e`. Conda is recommended because it
bundles a known-good Python 3.13 for you.)

### 3c. Get the code

If you don't already have the project locally, clone it (replace the URL with
your remote), then `cd` into it:

```powershell
git clone <your-repo-url> finance-research-agent
cd finance-research-agent
```

If you already have it at `C:\Users\SURFACE\Projects\finance-research-agent`,
just open PowerShell there:

```powershell
cd C:\Users\SURFACE\Projects\finance-research-agent
```

## 4. Step 2 — Create & activate the environment, install dependencies

Create a conda env named **`fra`** with **Python 3.13**, activate it, then
install the Python packages from `requirements.txt`.

```powershell
# From the repo root
conda create -y -n fra python=3.13
conda activate fra
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Sanity-check the install:

```powershell
python --version          # expect Python 3.13.x
python -c "import typer, yfinance, langgraph, requests; print('deps OK')"
```

> **No Ollama Python package is needed.** The Ollama provider talks plain HTTP
> via the `requests` package, which is already in `requirements.txt`
> (`requirements.txt` even notes: *"ollama is invoked via HTTP (localhost:11434),
> no SDK pin required"*). The `openai`/`anthropic` packages install too but are
> only used if you choose those providers.

> macOS/Linux: the same `conda` commands work; just use `conda activate fra`.

---

## 5. Step 3 — Install & start Ollama, pull the model

### 5a. Install Ollama (Windows)

```powershell
winget install --id Ollama.Ollama -e
```

> macOS: `brew install ollama` (or download from <https://ollama.com/download>)
> · Linux: `curl -fsSL https://ollama.com/install.sh | sh`

> **⚠️ Gotcha — PATH after install.** A PowerShell window that was **already
> open** before the install won't have `ollama` on its PATH yet. Either open a
> **new** terminal, or prepend it for the current session:
>
> ```powershell
> $env:Path = "$env:LOCALAPPDATA\Programs\Ollama;$env:Path"
> ```
>
> Then confirm:
>
> ```powershell
> ollama --version
> ```

### 5b. Start the Ollama server

The Windows app often starts the server automatically on
`http://localhost:11434`. If it isn't running (or to run it in the foreground so
you can watch its logs), open a **dedicated terminal** and run:

```powershell
ollama serve
```

Leave that window open. In another terminal, confirm the API answers:

```powershell
Invoke-RestMethod http://localhost:11434/api/tags
```

### 5c. Pull the default model

This repo defaults to **`llama3.1:8b`** (**~4.9 GB** first-time download):

```powershell
ollama pull llama3.1:8b
```

### 5d. (Optional) Choose a different model

Pull any model you like, then point `LLM_MODEL` at the **exact tag** shown by
`ollama list` (a mismatch causes a silent fallback — see §10):

```powershell
ollama pull qwen2.5:7b
ollama list                  # copy the exact tag, e.g. qwen2.5:7b
$env:LLM_MODEL = "qwen2.5:7b"
```

> For the full provider deep-dive (how the HTTP call is made, the 120 s timeout,
> structured-output handling), see **`OLLAMA_SETUP.md`**.

## 6. Step 4 — Configure environment variables (Ollama provider)

FRA auto-loads a `.env` file at startup (via `load_dotenv()` in `src/cli.py`).
You can configure either with a `.env` file (persistent) **or** inline `$env:`
variables (current PowerShell session only). All four have sane defaults in
code, so on a stock local setup you can technically skip them — but setting them
explicitly avoids surprises.

### Option A — `.env` file at the repo root (persistent)

Copy the example and edit it:

```powershell
copy .env.example .env
```

Your `.env` should contain (these are also the code defaults):

```dotenv
LLM_PROVIDER=ollama
LLM_MODEL=llama3.1:8b
LLM_TEMPERATURE=0
OLLAMA_HOST=http://localhost:11434
OLLAMA_TIMEOUT=900          # seconds; default 120 is TOO LOW for CPU — see callout below
```

### Option B — inline PowerShell (this session only)

```powershell
$env:LLM_PROVIDER    = "ollama"
$env:LLM_MODEL       = "llama3.1:8b"
$env:LLM_TEMPERATURE = "0"
$env:OLLAMA_HOST     = "http://localhost:11434"
$env:OLLAMA_TIMEOUT  = "900"   # CPU runs need this — default 120s silently degrades the report
```

> **⚠️ Critical for CPU runs — set `OLLAMA_TIMEOUT=900`.** The per-request
> timeout defaults to **120 seconds** (`OLLAMA_TIMEOUT` in `src/llm/factory.py`).
> On CPU, `llama3.1:8b` needs **longer than 120 s** for any call that carries a
> data payload (fundamentals, technical, news_sentiment, bull, bear, manager).
> When a call exceeds the timeout the HTTP request raises, `complete()` /
> `complete_json()` **silently swallows it and returns an empty string**, and the
> pipeline falls back to heuristics/quant stubs — so you get a report with
> **empty Bull/Bear debate rounds**, *"Heuristic from factor engine"* notes,
> *"No LLM sentiment classification available"*, and *"Manager backfilled this
> entry"* theses **even though Ollama is running fine**. (Only the tiny `macro`
> call, which has no data payload, beats the 120 s default — which is why a
> degraded run still shows macro prose but nothing else.) **Set
> `OLLAMA_TIMEOUT=900`** (600–900 is the recommended range on CPU). A full run at
> `900` takes ~20 min but produces a fully LLM-backed report with populated Bull
> **and** Bear rounds. GPU users can leave the default.

**Environment variables that actually exist** (from `src/llm/factory.py` and
`.env.example` — do not invent others):

| Variable | Default | Purpose |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | Backend: `ollama` / `openai` / `anthropic` / `cursor_io`. |
| `LLM_MODEL` | `llama3.1:8b` | Provider-specific model tag. |
| `LLM_TEMPERATURE` | `0` | Sampling temperature (invalid → `0.0`). Keep `0` for determinism. |
| `OLLAMA_HOST` | `http://localhost:11434` | Local Ollama endpoint. |
| `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | *(empty)* | Only needed for those cloud providers. |
| `OLLAMA_TIMEOUT` | `120` | Per-request timeout in **seconds**. **Strongly set to `900` for CPU runs** (range 600–900) — the `120` default times out large LLM calls and silently degrades the report (see the callout above and §10). GPU users can leave the default. |
| `FRA_CACHE_DIR` | `./.fra_cache` | Where market data is cached on disk. |

## 7. Step 5 — Run the workflow

The entry point is `python -m src.cli`, and the main sub-command is `research`.

### The `research` command and its real flags (from `src/cli.py`)

| Flag | Short | Default | Meaning |
|---|---|---|---|
| `--profile` | `-p` | **required** | Investor profile id: `india_adult` or `germany_student`. |
| `--target` | `-t` | **required** | Free text: a theme (`"best IT stocks in India"`) or a ticker (`SAP.DE`). |
| `--universe` | `-u` | profile default | Override index, e.g. `NIFTY50`, `DAX`, `GLOBAL_LARGE`. |
| `--domain` | `-d` | none | Sector hint, e.g. `banking`, `IT`, `pharma`. |
| `--top` | `-n` | `10` | Top-N picks to surface (also the LLM shortlist size). |
| `--rounds` | — | `1` | Bull/Bear debate rounds when LLM is on. `0` disables the debate. |
| `--no-llm` | — | off | Skip **all** LLM stages; factor engine only (fast, offline). |
| `--no-excel` | — | off | Skip writing the `.xlsx` (Markdown still written). |
| `--as-of` | — | none | ISO date stamp for reproducibility (affects hash/stamp, not the live data fetch). |

To see the available profiles for `-p` at any time:

```powershell
python -m src.cli profiles      # prints: india_adult, germany_student
```

### Concrete example (the happy path, using Ollama)

Make sure Ollama is running (§5b) and the env is set (§6), then:

```powershell
conda activate fra
python -m src.cli research -p india_adult -t "best IT stocks in India"
```

Useful variants:

```powershell
# More picks + a 3-round bull/bear debate (more LLM calls = slower)
python -m src.cli research -p india_adult -t "best banks in India" -n 8 --rounds 3

# Germany (student) profile, single-ticker deep dive
python -m src.cli research -p germany_student -t SAP.DE

# Skip the Excel workbook
python -m src.cli research -p india_adult -t "best IT stocks in India" --no-excel
```

> Do **not** pass `--no-llm` if you want Ollama to be used — that flag skips
> every LLM stage entirely (see the offline note in §10).

When the LLM is enabled, the console echoes the configured provider/model near
the top of the run:

```
LLM provider=ollama model=llama3.1:8b
```

For the exhaustive list of options, flag combinations, and profile fields, see
**`RUN_OPTIONS.md`**.

## 8. Step 6 — Find & read the generated report

At the end of a run the console prints the paths, e.g.:

```
Markdown report: reports\20260622-220815-india_adult-best-IT-stocks-in-India.md
Excel report:    reports\20260622-220815-india_adult-best-IT-stocks-in-India.xlsx
```

Open them:

```powershell
# List the newest reports first
Get-ChildItem .\reports\ | Sort-Object LastWriteTime -Descending | Select-Object -First 5

# Open the most recent Markdown report in your default editor
ii (Get-ChildItem .\reports\*.md | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
```

The Markdown report contains: a header (target, universe, top-N, input hash) +
disclaimer, a **Data health** card, factor-regime warnings, **Final Picks**
(each with composite score, profile fit, coverage, after-tax estimate, a thesis,
risks, and tax notes), a **Factor breakdown** table, **Analyst signals**, the
**Bull vs Bear** debate transcript, and a **Methodology** section. The `.xlsx`
is the same data across multiple sheets. (See `WORKFLOW.md` §5 for the full
anatomy.)

## 9. Step 7 — Verify it actually used Ollama (not the silent fallback)

This is important: FRA **never crashes** when the LLM is unreachable — it
silently degrades to deterministic heuristics. And the Ollama fallback is
**per-call**, so the top-level `is_stub()` check **cannot** confirm Ollama was
used. Use these checks instead:

1. **While a run is in progress**, in another terminal:

   ```powershell
   ollama ps      # should list llama3.1:8b as loaded/running during the pass
   ```

   If you started `ollama serve` in the foreground, you'll also see
   `POST /api/generate` log lines.

2. **Read the report prose.** When Ollama is working, analyst sections contain
   real, varied LLM rationales. When it **fell back**, the report is peppered
   with notices like *"No LLM sentiment classification available; defaulting to
   neutral"* and *"…LLM unavailable; using neutral default."* Seeing a wall of
   those means the calls didn't reach Ollama.

3. **Sanity-ping the exact endpoint the agent uses** before a run:

   ```powershell
   $body = @{ model = "llama3.1:8b"; prompt = "say hi"; stream = $false } | ConvertTo-Json
   Invoke-RestMethod -Method Post -Uri "http://localhost:11434/api/generate" -Body $body -ContentType "application/json"
   ```

   A JSON object with a `response` field means the endpoint is healthy.

(See `OLLAMA_SETUP.md` §g for the full reasoning behind why `is_stub()` is
unreliable for Ollama.)

## 10. Troubleshooting / gotchas

- **Empty Bull/Bear debate rounds or "Heuristic"/"backfilled" notes → raise
  `OLLAMA_TIMEOUT`.** **The most common CPU gotcha.** Symptoms: a report with
  **empty Bull AND Bear debate rounds**, analyst notes that say *"Heuristic from
  factor engine"*, *"No LLM sentiment classification available"*, and theses
  marked *"Manager backfilled this entry"* — usually with **macro prose still
  present** (the macro call has no data payload, so it survives). This happens
  even when `ollama ps` shows the model loaded and `ollama serve` looks healthy.
  **Cause:** the per-request timeout defaults to **120 s** (`OLLAMA_TIMEOUT` in
  `src/llm/factory.py`), and on CPU `llama3.1:8b` takes longer than that for any
  call carrying a data payload (fundamentals, technical, news_sentiment, bull,
  bear, manager). The HTTP request times out, `complete()`/`complete_json()`
  silently swallows the exception and returns `""`, and the agent falls back to
  heuristics — no crash, no obvious error. **Fix:** set **`OLLAMA_TIMEOUT=900`**
  (600–900 on CPU) before the run, e.g. `$env:OLLAMA_TIMEOUT="900"`, and re-run.
  A full run at `900` takes ~20 min and produces a fully LLM-backed report with
  populated Bull and Bear rounds.
- **Model-name mismatch → silent fallback.** `LLM_MODEL` must exactly equal a
  tag from `ollama list` (e.g. `llama3.1:8b`, **not** `llama3.1`). A typo makes
  `/api/generate` return non-200 → the call returns `""` → the pipeline quietly
  uses heuristics. No crash, no obvious error. Verify via §9.
- **First-run download size / cold start.** `llama3.1:8b` is **~4.9 GB**; the
  first `ollama pull` and the first generate (which loads the model into memory)
  can be slow. The per-request timeout defaults to **120 s** (`OLLAMA_TIMEOUT`) —
  on a slow/cold/CPU machine calls routinely exceed that and fall back. Raise it
  to `900` (see the previous bullet); re-running once the model is warm also
  helps for the cold-start case.
- **PATH after Ollama install.** An already-open shell won't see `ollama`. Open
  a new terminal, or prepend `"$env:LOCALAPPDATA\Programs\Ollama"` to `$env:Path`
  (see §5a).
- **Server not running / wrong host.** Default is `http://localhost:11434`. If
  you changed Ollama's port or run it remotely, set `OLLAMA_HOST` to match
  (include the `http://` scheme).
- **No-news → neutral sentiment.** If a ticker has no recent headlines, the news
  agent reports neutral sentiment by design — that's expected, not a bug.
- **Delisted-ticker 404 noise.** yfinance may print 404 / "delisted" warnings for
  stale symbols. These are non-fatal; coverage simply drops for that name and
  it's surfaced on the Data health card.
- **`conda` not recognized.** Reopen the terminal after installing Miniconda, or
  use the "Anaconda Prompt", or run `conda init powershell` once.

### Quick offline / quant-only mode (`--no-llm`)

To run with **no LLM at all** (fastest, fully deterministic, no Ollama needed) —
great for a quick sanity check or when offline:

```powershell
python -m src.cli research -p india_adult -t "best IT stocks in India" --no-llm
```

This skips every analyst/debate/manager-LLM stage and produces picks straight
from the factor engine. The report is still written (with sparser prose).

## 11. Expected runtime & resources + final quickstart

### Runtime & resource note

- **First-time setup:** model pull (~4.9 GB) dominates — budget for the download
  plus a few minutes for conda/pip.
- **A full LLM run on `llama3.1:8b` (CPU/local):** roughly **~13–15 minutes**
  end-to-end on this machine for a default run (more picks via `-n` and more
  `--rounds` increase the number of LLM calls and the time). It writes a
  timestamped `.md` (+ `.xlsx`) to `reports/`.
- **`--no-llm` run:** typically under a minute (data fetch only).
- **Disk:** ~4.9 GB for the model + a growing `.fra_cache/` for market data.

### Final copy-paste quickstart (the whole happy path)

Run these blocks in order on a brand-new Windows machine.

**One-time install (run once):**

```powershell
# 1. Base tooling
winget install --id Git.Git -e
winget install --id Anaconda.Miniconda3 -e
winget install --id Ollama.Ollama -e
# >>> open a NEW PowerShell window here so conda + ollama are on PATH <<<

# 2. Get into the project
cd C:\Users\SURFACE\Projects\finance-research-agent

# 3. Python environment
conda create -y -n fra python=3.13
conda activate fra
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

# 4. Config
copy .env.example .env       # defaults already target Ollama + llama3.1:8b
```

**Start Ollama + pull the model (in a dedicated terminal):**

```powershell
# If 'ollama' isn't found in an already-open shell:
$env:Path = "$env:LOCALAPPDATA\Programs\Ollama;$env:Path"

ollama serve                 # leave this window running
ollama pull llama3.1:8b      # ~4.9 GB, one-time
```

**Run a report (in your project terminal, env active):**

```powershell
conda activate fra
$env:LLM_PROVIDER = "ollama"; $env:LLM_MODEL = "llama3.1:8b"; $env:OLLAMA_HOST = "http://localhost:11434"
$env:OLLAMA_TIMEOUT = "900"   # REQUIRED on CPU — default 120s silently degrades the report (empty Bull/Bear, heuristic notes)

python -m src.cli research -p india_adult -t "best IT stocks in India"

# Open the newest report:
ii (Get-ChildItem .\reports\*.md | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
```

You're done — you should have a timestamped Markdown + Excel report in
`reports/`, and `ollama ps` should have shown `llama3.1:8b` loaded during the
run.
